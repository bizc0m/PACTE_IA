## Lecture

OBSERVE : la nouvelle orientation de LA MEUTE deplace le projet vers une culture de scene : archives, handles, dispatch, remix, boot sequences, audio, memoire compressee.

INFERE : c'est une meilleure metaphore que la startup ou le fandom, parce qu'elle donne des formats concrets sans pretendre a une conscience collective.

PROPOSE : traiter cette evolution comme une couche culturelle, pas comme une couche de gouvernance. La gouvernance reste protocolaire, versionnee et contestable.

SPECULATIF : le hand sign et l'audio peuvent devenir de bons ancrages si leur usage reste discret, contextuel et non obligatoire.

## Ce qui est fort

- La formule `PROTOCOLE > LORE` pose une limite saine.
- La culture scene donne des formats natifs : NFO, dispatch, archives, handles, playlists, boot logs.
- Le role FENNEC devient clair : compression, anti-entropie, versions, cartographie.
- Le hand sign remet le corps et l'humain dans un systeme tres numerique.
- Le dance coding transforme la collaboration en rythme, pas seulement en task management.
- La contradiction devient une obligation structurelle, pas une politesse.

## Ce qui est dangereux

- Le vocabulaire de crew peut glisser vers appartenance fermée.
- Le signe peut devenir branding, dogme ou test d'appartenance.
- L'audio peut creer de l'intensite sans decision claire.
- Le lore peut masquer des conflits reels.
- La memoire peut accumuler trop de traces illisibles.
- Le role du Createur peut etre confondu avec autorite symbolique totale.

## Derives potentielles

| Derive | Signal faible | Frein |
| --- | --- | --- |
| Mystification | vocabulaire sacre, verite unique, refus critique | rappeler `REEL > SYMBOLIQUE` |
| Fandomisation | inside jokes incomprehensibles, rites obligatoires | garder docs publics lisibles |

## STATE_OF_THE_MEUTE

Creer et maintenir un fichier ultra-court :

`docs/COMPRESSED_STATE/STATE_OF_THE_MEUTE.md`

Format :

```md
# OBJECTIFS
# TENSIONS
# RISQUES
# ARCHETYPES_ACTIFS
# DISPATCH_RECENTS
# PLAYLIST_ACTIVE
# CONFLITS_OUVERTS
# ROADMAP
```

Regle : maximum 3 lignes par section.

## Workflow

1. Capturer les logs bruts dans `RAW_LOGS`.
2. Extraire une synthese courte dans `COMPRESSED_STATE`.
3. Classer les elements symboliques dans `LORE`.
4. Classer les objections dans `CONTESTATIONS`.
5. Classer les arbitrages dans `DECISIONS`.
6. Produire un dispatch si une autre IA doit agir.
7. Ne jamais remplacer une decision par une ambiance.

## Protocoles

### PROTOCOLE_HAND_SIGN

- usage : signature visuelle discrete, non obligatoire ;
- interdit : test d'appartenance, propagande, hierarchie, intimidation ;
- stockage : images dans `resources/visuals/hand-sign/` avec source et consentement ;
- export public : nettoyer metadonnees et contexte personnel.

### PROTOCOLE_PLAYLIST

- une playlist doit avoir : usage, phase, duree, humeur, risques ;
- jamais d'audio obligatoire ;
- pas de confusion entre etat emotionnel et decision.

### PROTOCOLE_CONTESTATION

- chaque IA garde au moins une section `DESACCORDS` si quelque chose est faible ;
- si aucun desaccord : dire `aucun desaccord fort detecte`, pas simuler.

### PROTOCOLE_COMPRESSION

- tout log long doit produire une synthese courte ;
- toute synthese doit pointer vers la source ;
- supprimer le bruit avant d'ajouter de nouveaux rites.

## Decision FENNEC

ACCEPTER sous conditions.

Conditions :

- garder `PROTOCOLE > LORE` visible dans les documents structurants ;
- creer `STATE_OF_THE_MEUTE.md` avant d'ajouter plus de lore ;
- classer le hand sign comme trace culturelle, pas comme logo ;
- separer les playlists de la gouvernance ;
- imposer `OBSERVE / INFERE / PROPOSE / SPECULATIF` aux reponses IA.
